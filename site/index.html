O trabalho fica melhor quando cada passo tem um porquê.

Esse é o circuito que orienta a skill. Ele muda de tamanho conforme o problema, sem perder o compromisso com o resultado.

  1. 01

    Orientar

    Descobrir o objetivo, as restrições e o que provaria que o trabalho está pronto.

  2. 02

    Modelar

    Ler o código, os testes e o comportamento real antes de decidir o que mudar.

  3. 03

    Escolher o escopo

    Fazer uma correção precisa quando basta; planejar com mais cuidado quando há várias partes.

  4. 04

    Iterar

    Implementar, observar o efeito e ajustar a hipótese diante de novos dados.

  5. 05

    Verificar e entregar

    Testar no nível que importa e contar com clareza o que foi confirmado.

Este site também passou por esse circuito.

O fluxo de instalação foi testado em um Codex isolado. A versão vem do manifesto do plugin. A interface foi inspecionada em telas grandes e pequenas.

A sua cópia

Pronto para instalar, João?

São dois comandos no terminal do computador onde você usa Codex. A versão v{{VERSION}} fica fixada para você instalar exatamente o pacote publicado.

Código abertoSem telemetriaRemovível
1

Adicione a fonte

Isso apresenta o pacote ao Codex.

codex plugin marketplace add mSq-b12/evidence-driven-engineering@v{{VERSION}}

2

Instale a skill

Depois que o primeiro comando terminar, execute este.

codex plugin add evidence-driven-engineering@evidence-driven-engineering

Confirme dentro do Codex

Abra Plugins e procure Evidence-driven Engineering entre os instalados. Se o segundo comando não existir na sua versão, instale por essa tela após adicionar a fonte.

O navegador não consegue verificar plugins instalados no seu computador. A confirmação acontece no Codex.

Precisa de outro caminho?

Se o comando codex não for reconhecido, siga o guia oficial para instalar Codex. Se o pacote não aparecer, abra o guia de instalação do projeto.

Depois, dê a ela um problema de verdade.

Abra uma nova tarefa no Codex e experimente com algo pequeno do seu projeto. Você pode começar assim:

“Encontre um comportamento que não bate com os testes deste projeto. Mostre a causa, corrija o menor trecho necessário e verifique o resultado. Use Evidence-driven Engineering.”
