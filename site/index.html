01 / A cartaJF

Fiz uma coisa que queria colocar na sua mão.

Começou com uma pergunta simples: como trabalhar com um agente sem pular a parte de entender o problema? Estudei, testei, refinei e reuni o que resistiu aos testes nesta skill.

Ela não promete acertar sempre. Pede algo mais útil: investigar, escolher o escopo certo e mostrar evidências antes de dizer que terminou.

Agora você pode usar, adaptar e levar adiante. Braian

02 / A construção

Não nasceu pronta.
Precisou resistir.

O ponto de partida foram documentações públicas de ferramentas de agentes, depois adaptadas ao trabalho com Codex. Vieram uma primeira versão, revisão crítica, testes e novas versões. Cada rodada serviu para tirar o que não se sustentava.

  1. I / pesquisa

    Entender a ferramenta

    Capacidades, limites e formas de trabalho vieram antes das instruções.

  2. II / revisão

    Questionar a primeira resposta

    A skill passou por auditoria e red-team para expor lacunas e afirmações frágeis.

  3. III / prova

    Testar no uso

    Cenários e benchmarks ajudaram a separar boas ideias de instruções realmente úteis.

  4. IV / edição

    Publicar uma versão estável

    O pacote foi versionado e documentado para poder ser instalado, revisto e melhorado.

03 / O instrumento

Cinco movimentos.
Um critério.

Não é um roteiro rígido. É um circuito para ajustar o esforço ao problema e não declarar vitória antes de olhar a evidência.

01/ 05

Gire uma etapa para examinar o circuito

  1. 01Orientar↗

    Descobrir o objetivo, as restrições e o que provaria que o trabalho está pronto.

    Pergunta-guia: qual resultado mudaria a decisão?

  2. 02Modelar↗

    Ler o código, os testes e o comportamento real antes de decidir o que mudar.

    Pergunta-guia: o que o sistema faz hoje?

  3. 03Escolher o escopo↗

    Fazer uma correção precisa quando basta; planejar com mais cuidado quando há várias partes.

    Pergunta-guia: qual é a menor mudança honesta?

  4. 04Iterar↗

    Implementar, observar o efeito e ajustar a hipótese diante de novos dados.

    Pergunta-guia: o que aprendi com esta tentativa?

  5. 05Verificar e entregar↗

    Testar no nível que importa e contar com clareza o que foi confirmado.

    Pergunta-guia: que evidência sustenta a conclusão?

06 / A sua cópia

Pronto para instalar, João?

São dois comandos no terminal do computador onde você usa Codex. A versão v{{VERSION}} fica fixada para você instalar exatamente o pacote publicado.

Código abertoSem telemetriaRemovível
1

Adicione a fonte

Isso apresenta o pacote ao Codex.

codex plugin marketplace add mSq-b12/evidence-driven-engineering@v{{VERSION}}

2

Instale a skill

Depois que o primeiro comando terminar, execute este.

codex plugin add evidence-driven-engineering@evidence-driven-engineering

Confirme dentro do Codex

Abra Plugins e procure Evidence-driven Engineering entre os instalados. Se o segundo comando não existir na sua versão, instale por essa tela após adicionar a fonte.

O navegador não consegue verificar plugins instalados no seu computador. A confirmação acontece no Codex.

Precisa de outro caminho?

Se o comando codex não for reconhecido, siga o guia oficial para instalar Codex. Se o pacote não aparecer, abra o guia de instalação do projeto.

Depois, dê a ela um problema de verdade.

Abra uma nova tarefa no Codex e experimente com algo pequeno do seu projeto. Você pode começar assim:

“Encontre um comportamento que não bate com os testes deste projeto. Mostre a causa, corrija o menor trecho necessário e verifique o resultado. Use Evidence-driven Engineering.”
