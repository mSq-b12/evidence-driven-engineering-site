01 / A propostaE·E

Menos suposição. Mais trabalho que dá para conferir.

Evidence-driven Engineering é um conjunto de instruções operacionais para agentes que trabalham com código. Ajuda a entender o pedido e o sistema existente antes de escolher a mudança.

O esforço acompanha o risco: uma correção localizada pede um ciclo curto; uma alteração ampla pede contratos, limites e validação por etapas. O agente deve relatar o que realmente verificou — sem prometer infalibilidade.

Um guia de trabalho independente, aberto para inspeção e adaptação. Ver código e releases ↗

02 / Para quem desenvolve com agentes

O trabalho começa antes da primeira mudança.
Compreender vem primeiro.

O método organiza uma tarefa em cinco movimentos. Eles não são um ritual fixo: o agente escolhe o ciclo mais curto que ainda dê segurança suficiente para o problema.

  1. I / orientar

    Definir o resultado

    Entender o objetivo, as restrições e o que provaria que a tarefa está pronta.

  2. II / modelar

    Observar o sistema

    Ler os pontos relevantes do código, os testes e o comportamento atual.

  3. III / escopo

    Ajustar o esforço

    Escolher uma mudança pequena ou um plano, conforme o risco e a abrangência.

  4. IV / iterar

    Aprender com a tentativa

    Implementar, observar o efeito e atualizar a hipótese conforme os resultados.

  5. V / verificar

    Conferir e comunicar

    Executar as checagens pertinentes e explicar seus resultados e limites.

03 / O instrumento

Cinco movimentos.
Um critério.

Não é um roteiro rígido. É um circuito para ajustar o esforço ao problema e não declarar vitória antes de olhar a evidência.

01/ 05

Gire uma etapa para examinar o circuito

  1. 01Orientar↗

    Descobrir o objetivo, as restrições e o que provaria que o trabalho está pronto.

    Pergunta-guia: qual resultado mudaria a decisão?

  2. 02Modelar↗

    Ler o código, os testes e o comportamento real antes de decidir o que mudar.

    Pergunta-guia: o que o sistema faz hoje?

  3. 03Escolher o escopo↗

    Fazer uma correção precisa quando basta; planejar com mais cuidado quando há várias partes.

    Pergunta-guia: qual é a menor mudança honesta?

  4. 04Iterar↗

    Implementar, observar o efeito e ajustar a hipótese diante de novos dados.

    Pergunta-guia: o que aprendi com esta tentativa?

  5. 05Verificar e entregar↗

    Testar no nível que importa e contar com clareza o que foi confirmado.

    Pergunta-guia: que evidência sustenta a conclusão?

04 / Exemplo ilustrativo

De um sintoma vago a uma conclusão sustentada.

Imagine um botão de envio que parece funcionar, mas não conclui a ação. A skill orienta o agente a acompanhar o fluxo antes de escolher uma correção.

Leia a documentação completa ↗
Pedido

“O botão diz que enviou, mas nada chega.”

Investigação

Rastrear eventos, validação, resposta e testes do fluxo atual.

Verificação

Adicionar uma regressão para a causa encontrada e executar as checagens relevantes.

Cenário didático; não representa um bug ou resultado medido neste produto.

05 / Limites claros

Uma skill orienta o trabalho do agente; não substitui avaliação humana nem muda o modelo.

Instruções, não garantias.

O resultado continua dependendo do contexto, das ferramentas e das verificações disponíveis. A skill não executa tarefas sozinha, não instala um serviço e não promete que toda resposta estará correta.

06 / Instalação

Leve o método para o seu Codex.

Você precisa de uma versão atual do Codex com suporte a plugins e acesso Git ao repositório. A referência v{{VERSION}} identifica uma release fixada.

Código abertoSem telemetriaRemovível
1

Adicione a fonte

Isso apresenta o pacote ao Codex.

codex plugin marketplace add mSq-b12/evidence-driven-engineering@v{{VERSION}}

2

Instale pelo painel ou CLI

Prefira Plugins no Codex; use este comando se sua CLI oferecer suporte.

codex plugin add evidence-driven-engineering@evidence-driven-engineering

Confirme dentro do Codex

O primeiro comando adiciona a fonte; ele ainda não instala o plugin. Depois, instale Evidence-driven Engineering pela tela Plugins do Codex. Se sua CLI oferecer o comando, você também pode executar o segundo comando acima.

Confirme na lista de plugins instalados do Codex. Este site não consegue inspecionar nem verificar o que está no seu computador.

Precisa de outro caminho?

Se o comando codex não for reconhecido, siga o guia do Codex. Para atualizar, fixar outra release ou remover o plugin, consulte o guia de instalação e ciclo de vida.

Experimente em uma tarefa pequena.

Abra uma nova tarefa no Codex, mencione a skill e peça um resultado que possa ser verificado. Por exemplo:

“Investigue por que este formulário não conclui o envio. Primeiro entenda o fluxo e os testes existentes; depois proponha a menor correção e mostre o resultado das verificações. Use Evidence-driven Engineering.”

Evidence-driven Engineering é um projeto independente; não é produto oficial da OpenAI, Anthropic, Claude ou Codex.
